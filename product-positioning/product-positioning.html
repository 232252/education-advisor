01

执行摘要

本定位书基于对全部源代码（主进程 189 文件、渲染进程 280 文件）、配置体系与产品文档的全量调查写成，用于向产品负责人确认：这个产品是什么、为谁服务、应达到什么功能标准。

Education Advisor 是一款面向中国初高中班主任的本地优先（local-first）多智能体教育管理桌面应用：它把班主任每天约 2 小时的操行记录、成绩统计、家长沟通与周报撰写等文书工作，交给 18 个分工明确、权限受控的 AI Agent 和一个 Rust 事件溯源数据引擎处理，同时保证学生数据不出本机、每个数字可审计、每个模型可替换。

产品本质可以概括为三句话：

  • 它是一个「班主任驾驶舱」——用桌面应用（Electron + React）承载 12 个功能页面，覆盖仪表盘、学生、班级、学业、对话、Agent、模型、技能、调度、隐私、设置全流程；
  • 它是一个「教学团队操作系统」——18 个 Agent 各司其职（操行录入、风险预警、周报撰写、心理监测、家校沟通……），由 cron 定时或手动触发，按能力（capability）分级授权读写本地数据；
  • 它不是聊天机器人——每一个输出数字都必须来自工具调用而非模型「心算」，每一次写操作都落为 append-only 事件，可撤销、可回放、可审计。
目标用户

中国初/高中班主任（单人单班为主，默认 52 人班规模）；扩展至年级组长、德育主任。

核心价值

把每周 8–12 小时无教学价值的文书工作，压缩为「Agent 自动执行 + 班主任一键审阅」。

信任基石

本地优先 + 事件溯源 + PII 加密。产品起源问题：「机器帮我，但不把记录从我手里夺走。」

02

产品定位声明

用经典定位句式（Geoffrey Moore 模板）陈述产品的市场位置，并界定产品「是」与「不是」什么。

定位句式

对于每天被操行记录、成绩统计、家长沟通、周报撰写占据大量时间、又对学生隐私高度敏感的中国初高中班主任， Education Advisor 是一款本地优先的多智能体桌面工作台， 它可以把班级管理的记录、量化、分析、预警、报告全流程自动化，并保证每个数字可溯源、每条数据不出本机； 它不像通用 AI 聊天工具那样会编造数字、无法审计、要求把学生隐私上传云端。 我们的产品锚点是：每个数字来自工具调用、每个事件 append-only 可追溯、模型可随时换成 4B 本地小模型而系统照常工作。

产品性质界定

它「是」什么

  • 本地优先桌面工具Electron 43 + React 19 + TypeScript，Windows 安装包/便携版开箱即用，数据存本机磁盘
  • 多 Agent 教学团队操作系统18 个角色化 Agent，SOUL.md 人格 + capability 权限 + cron 调度
  • 班主任驾驶舱12 个页面覆盖操行、学业、班级、对话、自动化、隐私、运维
  • 开放模型层30+ 云端 Provider + Ollama 本地模型 + 自定义 OpenAI 兼容端点

它「不是」什么

  • 不是聊天机器人Agent 由工具约束，不是靠提示词祈祷；数字必须来自 eaa 工具调用
  • 不是 SaaS / 多租户平台ROADMAP 明确列为「不做」；数据所有权归教师个人
  • 不是 LMS（学习管理系统）不做教务排课、选课、成绩上报等学校级系统集成
  • 不依赖特定大模型AI 层无状态可替换：GPT-4o 换成 Qwen 4B，数据与流程不变

产品愿景

让班主任从文书工作中解放，把时间还给教学与人——同时让每一个教育决策都有据可查。项目自我定义为「teaching-team operating system（教学团队操作系统）」，而非又一个 AI 套壳产品。

目标用户与核心痛点

产品的一切功能设计都锚定在一个具体的人与一个具体的时刻：晚上 11 点还在整理纸质操行记录的班主任。

「我每天花 2 小时做记录和报告，机器能不能帮我，但不把记录从我手里夺走？」 —— 产品的起源问题（PROJECT_INTRO.md），来自一位真实班主任

用户画像

核心用户：班主任 主画像

  • 日常以「+2 / −3」操行积分管理课堂与宿舍纪律

典型使用场景

  • 课间 30 秒：班主任对桌面应用（或飞书）说一句「张三 课堂讲话」，class-monitor 通过原因码记录 −2 分，事件即刻落盘；
  • 每日 21:00：psychology Agent 巡检事件历史，识别心理危机信号（只标记、不写入）；risk-alert 工作日 8:00 扫描高危学生；
  • 周五 16:00：weekly-reporter 自动起草班级操行周报，班主任审阅后导出或同步飞书；
  • 家长质疑时：事件日志 append-only + 哈希链 + 完整审计记录，随时拿出证据链。
04

差异化卖点

产品文档明确了通用 chatbot 在教育场景的三个失败模式，本产品逐条对位设计了自己的护城河。

1 · 不幻觉数字

所有 Agent 提示词遵守「小模型规则手册」：没有从工具读到的数据 = 不存在；禁止模型心算，每个数字必须来自 eaa 工具调用，输出经 JSON Schema 校验。

2 · 完整审计链

事件日志 append-only、可选 SHA-256 哈希链防篡改；撤销 = 追加对冲事件而非删除。家长质疑时，证据链完整可回放。

3 · 小模型可用

Agent 由工具与规则约束而非依赖模型智力——3–4B 参数模型（如 Qwen 4B 本地跑）系统照常工作，API 成本可降至零。

4 · PII 本地加密

Rust PII 引擎用 AES-256-GCM 建「姓名→S_017」加密映射表；按接收方过滤（LLM 激进脱敏 / 家长只脱敏他人 / 教师本人直通），每次调用写审计日志。

5 · 本地优先

Rust 事件引擎管理全部读写、文件锁与原子落盘；LLM 是唯一出网组件，且只见脱敏后的数据切片。

6 · 成本可控

模型分层路由：18 个 Agent 中 14 个走低成本档、4 个走高质量档；产品宣称高质量+低成本组合下每班每天 API 费用 < 1 元。

七条设计原则（架构层的不可妥协项）

  1. Rust 侧永远是数据真源（single source of truth）
  2. 工具调用而非「感觉」——数字全部来自工具
  3. append-only：事件无删除、无覆盖，只能 revert 对冲
  4. PII 默认不出本机：加密 + 假名化 + 按接收方过滤
  5. 小模型大提示词：为 3–4B 模型设计，大模型只是更快
  6. 本地优先、云端可选：拔掉网线，记录照常工作
  7. 可复现构建：npm ci → build → package 产出字节级一致的安装包

功能全景：应达到的功能

以下按六大能力域陈述产品「应该达到的功能标准」——每一条都对应已实现的页面与服务代码，可直接作为验收清单。

能力域 1 · 班级操行量化管理（产品核心）

承载页面：Dashboard / Students · 承载服务：eaa-bridge + Rust eaa-cli（24 个 IPC 通道）

  • 学生档案 CRUD 与批量管理新增/删除（二次确认）/元数据设置（分组、职务、班级）；JSON 批量导入；CSV/JSONL/HTML/JSON/TXT 多格式导出
  • 原因码体系计分22 个内置原因码：11 个扣分（−1~−10）、6 个加分（+1~+10 含变量分）、1 个系统撤销码、4 个实验室专项码
  • 事件记录与撤销加扣分事件即时落盘；支持 dryRun 预演；撤销走 revert 对冲事件，绝不物理删除
  • 多 维 检 索按学生查分/查历史、关键词搜索、时间范围、标签过滤、Top-N 排行榜（含缓存与写后失效）
  • 风险分级操行分口径：< 60 极高 / 60–80 高 / 80–100 中 / ≥100 低；Agent 判定阈值统一为 85/93
  • 统计与治理数据统计、事件校验（validate）、健康检查（doctor）、全量重放排名（replay）、HTML 仪表盘导出
  • 仪表盘5 张统计卡（学生数/有效事件/撤销/分数变动或班级均分/高风险数）、分数分布与风险分布图、原因码 Top8、排行榜 Top10（点击直达学生档案）、周期涨跌摘要、全班级对比模式

  • 系统设置主题（亮/暗/跟随系统）、语言（中/英）、开机自启、最小化到托盘、关闭行为三态、日志级别、自动更新与更新源
  • 日志体系main/chat/renderer 三类日志实时查看：级别过滤、防抖搜索、导出、清空；Agent 侧日志自动脱敏
  • 诊断与更新EAA 健康检查、数据完整性验证、更新检查（semver + GitHub Releases）、系统托盘、快捷键（Ctrl+1..9 切页）
  • 安全边界渲染进程零 Node 权限、IPC 输入 TypeBox 校验、命令注入/路径穿越/NUL 字节防护、文件读取 10MB 上限、CDP 生产强制关闭

调查发现：文档与实现的偏差

全量代码扫描中发现的「文档说」与「代码是」不一致之处——这些点需要产品负责人裁决，属于定位书应当如实呈现的部分。

1

main Agent 的人格文件为空。agents/main/SOUL.md 是空文件，完整提示词实际存放在平铺文件 agents/main.md（标注「Recovered from v0.1.0-rc.1」）。主协调 Agent 的人格加载依赖目录约定，需确认运行时取到的是哪一份。

2

8 个 AGENTS.md 内容完全相同。academic、executor、home_school、psychology、research、safety、supervisor、validator 的 AGENTS.md 均为框架通用模板（讲工作区与记忆机制），并非各 Agent 专属规则；文档宣称的「SOUL + AGENTS 双文件定制」实际只有 SOUL 是专属的。

3

原因码数量不符。PROJECT_INTRO 称 24 个原因码，config/reason-codes.json 实际 22 个（11 扣分 + 6 加分 + 1 系统 + 4 实验室）。

4

隐私引擎默认关闭。config/default-settings.json 中 privacy.enabled: false、autoAnonymize: false，与文档「隐私引擎默认常开」的表述不一致——对一款把隐私作为核心卖点的产品，这是定位层面需要澄清的选择。

5

IPC 通道统计口径不一。SWARM_ARCHITECTURE.md 统计为 97 个通道，本次代码调查实测约 125 个（16 个命名空间）——文档滞后于代码。

6

技术栈版本描述滞后。README 徽章写 React 18 / Electron 33 / TS 5.7，package.json 实际为 React 19.2 / Electron 43 / TS 7.0 / Vite 8 / Tailwind 4。

结论

Education Advisor 的定位是清晰且自洽的：一款本地优先、事件可审计、模型可替换的班主任多智能体桌面工作台，核心是操行量化管理，扩展面是学业分析与家校协同，护城河是「不幻觉数字 + 完整审计链 + PII 本地加密」。

代码实现与定位陈述总体高度吻合（功能面、架构、Agent 编制均有代码实证）；上述 6 处偏差属于文档滞后或个别配置选择，不影响定位成立，但建议在下一个版本收敛——尤其是隐私引擎默认开关与 main Agent 人格文件两处。
