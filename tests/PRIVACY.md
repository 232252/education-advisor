# 测试数据隐私规范

本仓库已开源,测试/文档中**禁止出现任何真实学生、教师、家长的个人信息**。
历史中曾混入的真实数据已于 2026-09 彻底清除并重写 git 历史(见 scripts/privacy-gate.mjs)。

## 虚构数据约定

| 类型 | 约定 | 示例 |
|---|---|---|
| 学生/家长姓名 | `测试甲` `测试乙` … / `测试家长甲` | `['1', '测试甲', '男', …]` |
| 身份证号 | 区号用**不存在的 `990000`** 开头,校验码按 GB 11643 算合法值 | `990000200801011232` |
| 手机号 | 白名单里的虚构号(scripts/privacy-allowlist.txt) | `13800001111` |
| 地名 | `示例县` `示例镇甲` | |
| 邮箱 | example.com 等占位域名 | `test@example.com` |

`990000` 区号在行政区划中不存在,`99`/`00` 开头的证件号一律视为虚构数据;
校验码仍需合法是因为 `src/shared/id-card.ts` 会做 GB 11643 校验。

## 门禁

- **本地提交**:`.githooks/pre-commit` 扫描暂存区(`npm install` 后自动启用)。
- **推送/PR**:GitHub Actions `privacy-gate` 工作流全量扫描。
- 拦截规则:手机号 / 身份证 / 非占位邮箱 / 数据文件(.xlsx/.csv/.env…) /
  哈希黑名单 / **本地花名册交叉比对**。
- 误放行的虚构常量加进 `scripts/privacy-allowlist.txt` 并注明理由。

### 本地花名册交叉比对(重要)

只靠哈希黑名单是不够的:黑名单只能拦住**已知**的泄漏。2026-09 的
`benchmark/` 目录就是这样漏掉的 —— 5 名真实学生姓名(能在本地库里查到)
被当作查询串写进脚本,而它们从没进过黑名单,门禁因此报"通过"。

现在门禁会在本机存在真实 EAA 数据(`.eaa-data/`,`gitignore` 已排除)时,
把库里的真实姓名**逐个**拿来比对所有被扫描的文件。这条规则不依赖黑名单,
能抓住第一次出现的泄漏。库不存在时(CI、全新 clone)自动跳过,不影响门禁跑通。

因此:

- 在**有真实数据**的机器上跑 `npm run privacy:gate`,会额外做花名册比对 —— 这是
  最严格的一档,提交前建议本地跑一次。
- CI 上只有黑名单与格式规则(CI 没有真实库),防线仍靠本地这一档兜住。
