# 教育参谋 × DeepSeek Harness：现状与插件化计划

桌面端的 Agent 循环已经走 DeepSeek Harness **0.2.2-rc.1**（`createDshAgent`），不再创建 Pi Agent。连接中心的页面是官方 **dsh-im 5.10.0**（`vendor/dsh-im`，与 npm 发布产物一致）。宿主只负责窗口、密钥、dsh 进程和插件目录。

官方 `integrations/desktop-panel` 只在桌面 iframe 里启用（`window.parent !== window`）。教育参谋用的是顶层 `WebContentsView`（登录 cookie 是 SameSite=Strict，跨源 iframe 会丢），所以侧栏入口放在 `vendor/dsh-im/integrations/eaa-panel`，槽位和 `dshImClient` v1 与官方接入说明一致。

## 已经接到 dsh 上的

| 能力 | 现在怎么跑 |
|:-----|:-----------|
| 教师 AI 对话的模型循环 | 主进程用 `@deepseek-ai/dsh-sdk-client` 拉起 `dsh` 子进程，走 `initialize` / `prompt` / `subscribe`。子进程是随包的 Node，不是 Electron 自己的 exe（0.2.1 的原生模块不认 43.2.0 这份指纹）。模型页不再提供切回 pi 的开关；设置里残留的 `agentRuntime: pi` 打开模型页时改回 dsh。批改、模型页的连接测试都只走 dsh。连接测试会带上输入框里还没保存的密钥。设置里的「自动压缩对话」在发给 dsh 之前生效：教师对话先压缩再进子进程；智能体历史先化名再压缩。摘要失败就按字符截断。「对话日志」打开时，提问、回复文本和工具调用写入 `logs/chat-*.log`；关闭后不再写入。「引导模式」决定回复结束后怎么发出排队消息：全部合成一条，一次一个则只发下一条。点停止不会把排队消息立刻发出去。已经取出但还没发出去时如果被打断，会放回队首。系统提示里的引导模式与排队一致：本轮不会中途插入新指令。思考级别只列出当前模型目录里有的档；没有的档这一轮按关闭发送 |
| 工具白名单 | 仍由本仓库的 hardening patch 关掉 bash、文件、网页、子代理等模型侧工具，只留教育参谋自己的工具桥。模型调用时用 `mcp__服务名__工具名`；对话气泡和运行页只显示工具自己的名字 |
| 连接中心 | 独立 `DSH_HOME` 里的 `dsh web`，用 `link:` 装上 `vendor/dsh-im` 和 `eaa-panel`。启动时带上和教师对话同一份加固补丁、同一批模型密钥，并挂上主协调的教育工具。渠道里的回复按主协调的说明办事。页面贴在主窗口侧栏右侧，窗口偏窄时铺满，并且不超出窗口，避免官方左右栏被挤成上下堆叠，也避免关闭按钮被挤出屏幕。视图位置只在面板尺寸变化时更新。已经打开时，跟着改尺寸不再把键盘抢进网页。外壳只留关闭和「数据同步」；嵌进来时收起 Harness 侧栏，藏掉官方页的 DSH-IM 标题、插件自更新和 GitHub。通用设置仍留在官方页里。收侧栏的样式只打在带侧栏标记的外层框架上，不改官方分段选项卡和诊断详情的列宽。宽屏时页面锁在窗口高度里，标题不再占空边，普通窗口能放下整列频道；窗口更矮时频道栏和右侧各自滚动。打开后停在 IM 机器人，默认飞书。已确认过的「预览版说明」写进 web 配置，并关掉 dsh 自己的 API Key 弹层，登录页不再被挡。渠道会话默认用教育预设：只挂说明、技能和教育工具。web 自带预设把命令行装在预设里面，宿主加固补丁按行号盖不到，所以启动时再写一份预设补丁，把标准、精简、ptc、cordis 里的命令行、文件、网页和子代理关掉。技能目录写在教育预设自己的 skill-filesystem 上。已经选过标准、精简、ptc 或 cordis 的旧会话，技能目录同样只扫描这一份，人设也改成班级操行助手。选择器上的名称和说明改成实际还能做的事。精简模式原来只有命令行，关掉之后补上同一份技能和说明 |
| 本机频道与 WebUI | 设置页和技能页的插件中心都打开同一块 IM 插件。插件中心列出聊天、花名册、成绩、批改和操行。花名册、成绩、批改和操行要在教师对话和连接中心两边的安装戳都对上当前版本才显示「已接入」，对不上写「未接入」；聊天连接的戳只看 web。刷新会重读这些戳。不再向旧频道适配器查询飞书状态。飞书、企微、钉钉、QQ、微信、Slack、Telegram、Discord、Matrix 不再由旧适配器开机自启。飞书多维表格同步和教师推送仍用设置里的开放平台 App ID / Secret，和 IM 插件里的扫码登录不是同一套凭证。本机 WebUI 仍留在设置里，手机二维码跟在正在监听的局域网地址旁边 |

## 功能清单：现状 → 插件

原则和 dsh 一样：一个功能一个插件，用 `cordis.patch.yml` 声明插入点，profile 决定装不装，坏了只卸这一个，不改主程序。

| 桌面功能 | 现在的位置 | 建议插件 | 优先级 |
|:---------|:-----------|:---------|:-------|
| 操行查询 / 加减分 / 排名 | `vendor/eaa-tools`。公开名 `mcp__eaa__*`。这次运行没有操行工具就不注入 `EAA_MCP_URL`。插件中心读 sdk 与 web 的安装戳，两边都对上 `包名@版本` 才显示已接入；聊天连接只看 web 上的 `eaa-dsh-im.stamp` | 文件、委托仍留在这一组 | 高 |
| 学生 / 班级档案 | `vendor/eaa-roster`。公开名 `mcp__roster__*`。页面仍是 `/students` `/classes` | 卸掉它不影响操行查询 | 高 |
| 成绩与学业预警 | `vendor/eaa-grades`。公开名 `mcp__grades__*` | 预警叙述仍由学业角色的说明负责 | 高 |
| 作业批改 | `vendor/eaa-grading`。公开名 `mcp__grading__*` | 未归组不猜姓名的规则仍在工具实现里 | 高 |
| 周报 / 督导 / 谈话计划 | `agents/*` 定时任务 | `eaa-agents`：每个角色一个插件，调度只负责叫醒 | 中 |
| 家校草稿 | home_school 角色 | `eaa-home-school`：只出草稿，不发送 | 中 |
| 安全 / 纪律记录 | safety、discipline-officer | `eaa-discipline`：原因码与确认协议留在插件里 | 中 |
| 技能 | 正文仍在 `skills/` 和用户技能目录。每次运行复制该角色看得到的那一份，改成 dsh 的短横线名字，由 `tool-skill` 加载。页面 `/skills` 仍是编辑入口 | 中 |
| 定时任务 | `/scheduler` 仍由宿主叫醒角色 | dsh-schedule 只往已经打开的会话里投提醒，替不了早上没人对话也要跑的日报 | 中 |
| 模型与密钥 | `/models` | 留在宿主：密钥不进插件仓库 | 低（宿主职责） |
| 隐私引擎 | `/privacy` | 留在宿主：脱敏发生在工具结果离开本机之前 | 低（宿主职责） |
| 报告中心 | `/reports` | `eaa-reports`：读已有快照写文件，不自己改操行数据 | 低 |
| 设置 / 更新 / 托盘 | `/settings`、托盘 | 留在 Electron 宿主 | 不做插件 |

宿主永远留下的只有四件事：窗口与更新、密钥与隐私、dsh 进程、插件安装目录。其余页面都应该能单独开关。

## 接下来按这个顺序做

1. **连接中心只留官方插件。** 侧栏和设置页打开的是同一块 dsh-im。设置页剩下的是多维表格同步，不再放一套旧频道卡片。
2. **教师对话和连接中心共用一套工具。** sdk profile 负责应用里的对话；web profile 负责 dsh-im 收到的渠道消息。两边都由宿主注入 MCP、写操作确认和隐私脱敏，学生数据不进插件包。
3. **一个功能一个插件。** 花名册、成绩、批改已经各自是插件，和操行插件并排装进 web 与 sdk。某次运行的工具集里没有某一组，宿主就不给那组地址，插件保持关闭。坏了只卸这一个。
4. **技能用 dsh 自带的 skill 插件。** 正文留在本仓库。模型用 `skill` 工具加载，不再从系统提示里拿一份 `read_file` 清单。定时任务仍由宿主调度：dsh 的 schedule 插件解决不了「没开会话也要出日报」。
5. **升级插件不改壳。** `vendor/dsh-im` 跟官方 zip 的程序文件对齐；版本对不上时用 `dsh plugin allow-version`，不在主程序里打补丁。

## 远景

目标是教育参谋变成一个很薄的 Electron 壳，真正的能力都是 dsh profile 里的插件，和 DeepSeek 自己的桌面端同一套装拆方式。

1. **一个 profile，多块插件。** `web` 给连接中心，`sdk` 给教师对话。教育插件同时声明自己要插进哪边：工具进 sdk，界面进 web 的 sidebar slot。
2. **插件自己带契约。** 每个插件写明能读什么、能写什么、写之前要不要教师确认。主程序不再认识「迟到扣几分」，那是纪律插件和原因码字典的事。
3. **坏了就卸。** 批改插件出问题，卸掉它，操行查询和连接中心照常。版本对不上时走 `dsh plugin allow-version`，不在主程序里打补丁。
4. **数据仍在本机。** 插件通过宿主给的工具读学生数据，不把花名册、身份证、成绩复制进插件包，也不进 git。
5. **维护方式。** 主仓库只发壳和 profile 模板。功能以独立包迭代，教师端 `dsh plugin add` 升级某一个，不用为改一个页面重打整个安装包。

这样做的直接好处：连接中心已经能跟着 dsh-im 的版本走；后面的批改、成绩、周报也可以按同样的节奏单独修，不必每次都改 Electron 主进程。
