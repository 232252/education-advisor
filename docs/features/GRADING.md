# AI 批改作业（Grading）— 功能指南

内置的 AI 批改子系统：教师在本机完成「建任务 → 传试卷 → AI 按量规批改 →
教师复核 → 发布进学业分析」的完整闭环。侧边栏一级入口「批改作业」。

> 数据模型与批改流程以开源项目 [Submitty](https://github.com/Submitty/Submitty)
> 的改卷链路为蓝本（量规 → 逐题给分 → 教师覆盖 → 发布），上游 schema 以
> `vendor/submitty/` 参照面形式内置并随上游月度发版更新（见
> `vendor/submitty/README.md`）。

## 使用流程

1. **新建任务**（侧边栏 → 批改作业 → + 新建任务）
   - 填任务名/学期/日期/班级/科目；在量规编辑器里录入每道题的
     **题号、满分、参考答案或评分标准**（这是 AI 的判分依据，越具体越准）。
2. **导入试卷并归组**
   - 支持批量多选 jpg/png/webp/bmp（PDF 请先转为图片）；
   - 文件名含学生姓名时会自动给归属建议（唯一命中才建议），一键应用或人工指认。
3. **标记就绪 → 开始 AI 批改**
   - 逐份串行批改，实时进度条；可随时中止，已完成的结果保留；
   - 失败的试卷（网络/模型原因）可单独「重试失败试卷」。
4. **复核**（双栏工作台：左原图、右逐题给分）
   - 每题可见 AI 得分与判分依据；教师可改分/写评语（改分优先于 AI 分）；
   - 总评 + 生效总分实时合成；上一份/下一份快速切换。
5. **发布成绩**
   - 任务 → 一场考试（scope 标记 `ai-grading`），每道题 → 一个科目（如「1.选择题」），
     另加「总分」科目；写入既有学业管线，**考试分析/学生档案/报告中心/Agent 全链路自动可见**；
   - 重复发布幂等（同一考试覆盖更新）；未归组/未批改/分数不完整的试卷会列入跳过清单。

## 批改模型

- 设置入口：**设置 → 模型 → 批改模型**（也可从批改页错误提示跳转）；
- 只列出**支持图像输入**的视觉模型；未选择时跟随「高质量模型」（若该模型不支持
  看图，启动批改会明确报错）；
- API Key 复用各 Provider 的既有配置（Keystore 加密存储）。

## 与其他子系统的联动

| 面 | 说明 |
| --- | --- |
| 学业分析 | 发布后 `eaa_exams` / `eaa_exam_grades` / `eaa_student_grades` 可查 |
| 对话/Agent | `eaa_grading_overview` / `eaa_grading_student` 两个只读工具（`academics` 能力），配 `skills/AI_GRADING.md` 技能；隐私脱敏自动包裹 |
| 备份/恢复 | `<数据目录>/grading/`（任务 JSON + 试卷扫描件）随全量备份 |
| 日志 | 统一日志（scope `grading`），设置 → 日志 可查 |

## 数据与存储

- 任务 JSON：`<appData>/grading/tasks/<taskId>.json`
- 试卷扫描件：`<appData>/grading/files/<taskId>/`
- 状态机：草稿 → 已就绪 → 批改中 → 待复核 → 已发布（已发布可回流复核改分再发布）

## 常见问题

- **AI 批改失败**：看试卷行的错误提示（悬停）；常见为模型不支持图像、API Key
  失效、网络超时；处理后点「重试失败试卷」。
- **归组建议不出现**：检查文件名是否含学生完整姓名；歧义命中（如「张三/张三丰」）
  一律留给人工指认。
- **想改量规**：仅草稿/已就绪态可改；已有批改结果后量规锁定（保证逐题结果
  始终对应一套稳定量规），需要时请新建任务。
