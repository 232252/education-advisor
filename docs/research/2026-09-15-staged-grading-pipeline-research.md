# 调研报告：分阶段批改流程 —— 分题型分批 + 条件复验 + 区域裁剪

> 日期：2026-09-15 ｜ 性质：**只调研，不动代码**
> 背景：用户实测观察——**量规里知识点/评分点一多，批改准确率直线下降**。方向指示：批改要有步骤、分题型分批走，批完要复验（同模型复验即可，双模型可选），不一致则重改；复核时把对应题目区域**裁剪出来单独批阅**，而不是整张图直接喂。本报告在用户明确约束下完成：**不调研模型价格、不以"换便宜模型/免费档"为前提——同一个模型、同一套配置，纯靠流程规划（调用次数怎么分、每次喂什么、输出预算给多少、复验怎么触发）达到又准又省**。价格今天免费明天收费，流程性价比必须以「**调用次数 × 每次输入/输出 token**」度量才长期成立。
> 术语：本文"一次调用"= 一次完整视觉模型请求；"思考 token"= 推理模型（thinking/reasoning）的内部推理 token；"批"= 一次调用承载的题目范围。

## 0. 速览结论

1. **"知识点一多准确率直线下降"不是玄学，是四个可指认的机制叠加**，全部源于现行"整卷一次调用"的形态（`grading-pipeline.ts` `gradePaperOnce`）：
   - **输出预算挤兑**（第一嫌疑）：`GRADING_MAX_TOKENS = 8192` 是**整卷全部题目 JSON + 批注 + 扣分说明 + 思考 token** 共享的输出上限。题多/评分点多 → 输出逼近上限 → 模型压缩思考或截断 JSON → 判分质量下降。
   - **量规稀释**：一次调用里塞整卷量规，判分条目越多，指令遵循质量越差（LLM-as-judge 实证，见 3.2）。
   - **注意力/分辨率摊薄**：多页整卷图一次给，模型每道题都要先"全卷找位置"，手写小字在整页缩略里读不细（本库 `identify-papers.ts` 已经用"裁顶部放大"解决了同类问题）。
   - **多任务串扰**：读题/定位/判分/写批注/算 box 在一次调用里同时做，互相挤占。
2. **分批批改 = 输出预算重分配**，这是提准的主发动机：从"整卷 8192 全题分摊"变成"每批独立 1k–4k"。逐题批改时每题可用输出+思考预算是现状的 **5–10 倍**，思考型模型"先想清楚再判"的空间才真正存在。
3. **裁剪不是多花钱，是省算力**：A4 300dpi 整页 ≈ 8.7M 像素；各家视觉 API 图像 token 都按像素/切块线性计（OpenAI 512px 切块、Gemini 768px 切块、Qwen 像素/784）。**一道题的区域裁剪图 token 约为整页的 1/8–1/10**。分 8–12 次调用送裁剪图，总输入图像 token 与送 1–2 次整页相当甚至更少——**次数升、总 token 不升**。
4. **裁剪同时提准有直接证据**：视觉提示研究里"圈定/放大目标区域"是提升视觉判读的最大单项（Set-of-Mark 让 GPT-4V 定位 25.7%→86.4%；TextCoT"先概览后放大"专治文字密集图；OpenAI "thinking with images" 把自动裁剪/放大做成模型内建能力，V* 基准 95.7%）。**先识别定位 → 裁剪 → 单题批改正是用户设想的路线，也是商用 AI 阅卷（阿里云"智能分题：按需圈定题目区域"）和高考网上阅卷（答题卡分题切块、一屏一题）的通用形态。**
5. **同模型复验有效且便宜**：自洽性（同模型多次采样+投票）在推理任务上有 +17.9%（GSM8K，40 路采样）量级的实证提升，5–25% 是普遍区间——**不需要第二个模型**。LLM 单次评分本身有方差（Rating Roulette），复验的价值是把"随机漂移"与"系统性判错"分开：两次一致 → 大概率稳；不一致 → 该题有问题，值得花一次重改。
6. **条件触发是成本的关键**：被 09-13 否决的是"全量双评"（每卷固定 2× 成本）。本次方案是**单评 + 条件复验**：只对触发信号的题复验（分差大/自报字迹不清/解析可疑/贴边界），期望成本 = 1 + 触发率 p（预期 10–30%），而非 2×。**这沿用了高考双评的"分差阈值"思想，但把第二评从"全量"改成"条件触发"。**
7. **批改顺序：诚实结论——分批之后，先改哪类题对准确率本身影响很小**（各批独立调用，互不抢预算）。顺序的真正价值在：①客观题先锁定（转写+规则判分，判分错误清零、成本近零）②失败早暴露（量规/配置错误在第一批就炸，不用整卷跑完才发现）③分数渐进出（老师体验）。**推荐顺序：单选 → 多选 → 填空(1–2 小题/批) → 大题逐题**——与用户直觉、与网上阅卷三段式（客观题机器阅先行 → 主观题分题流水）完全同构。
8. **客观题"转写+规则判分"应当并入本流程**（09-13 已保留的零成本项）：单选/多选批次只让模型**转写**学生答案（如 `1-5 BACDA`），判分由代码与 `referenceAnswer` 比对完成。转写比判分容易得多，且把"选错认读"类错误清零。
9. **输出上限问题独立成立**：无论是否分批，`8192` 对"整卷一次出全部题"都是紧的（算术见 1.1）；推理模型思考 token 计入输出预算是各家通行行为（OpenAI 官方明确 reasoning tokens 占 `max_completion_tokens` 并按输出计费；预算耗尽返回 incomplete）。**分批让每批上限从"被动钳制"变成"主动配给"。**
10. **长远目光（用户要求）**：模型越强，流程档位应当能"拧回去"——本方案所有档位（批粒度/复验开关/触发阈值）做成配置项，配一个**回归集**（已复核任务里 AI 分 vs 教师生效分）作为"换档依据"。今天的"逐题批"在模型进步后可以拧回"题组批"，架构不用重写。

## 一、问题诊断：为什么"知识点一多，准确率直线下降"

### 1.1 输出预算挤兑（第一嫌疑机制，用户点名的 8192）

现行单份卷批改（`gradePaperOnce`）：

```
输入 = 全部页图(原图 base64, 不缩放) + 全量规(system prompt)
输出 ≤ 8192 tokens = Σ(每题 JSON) + 思考 token(若思考型模型)
```

一笔账（物理卷典型：8–10 个大题量规条目，大题内含小题）：

| 输出构成 | 单条量级 | 全卷累计 |
|---|---|---|
| 每题 JSON（score/evidence≈30字/comment≈30字/deductions≤8条/box/marks） | 150–400 tokens | 1.5k–4k |
| 思考 token（逐题读手写+对评分标准，每大题 200–600） | — | 2k–6k |
| **合计** | — | **3.5k–10k，常态性逼近/越过 8192** |

后果按模型行为分两种，都伤准确率：

- **压缩思考**：模型感知到输出预算紧（长 prompt 里它对剩余预算有隐式感知），减少推理深度，直接"拍分"——评分点越多越明显：**这正是"知识点一多，直线下降"的形态**；
- **截断 JSON**：输出到 8192 被硬截 → 解析失败/修复解析兜底（本库 `parseGradeResponse` 的四层容错与"截断修复"就是为这个现象准备的）→ 该卷 failed 或尾部题目丢失。

旁证：推理模型思考 token 计入输出上限是行业通行行为——OpenAI 官方文档明确 reasoning tokens 计入 `max_completion_tokens`、按输出计费、预算耗尽返回 `status: incomplete`（[OpenAI 社区/文档](https://community.openai.com/t/why-was-max-tokens-changed-to-max-completion-tokens/938077)、[OpenRouter 文档](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)）。**用户判断"8192 对一套题绝对不够（还没算思考）"成立。**

### 1.2 量规稀释（判分指令条目越多，遵循越差）

- LLM-as-judge 实证：量规的**长度与顺序**都显著影响判分准确率，随机排列量规条目会拉低所有裁判模型的准确率（[Evaluating Scoring Bias in LLM-as-a-Judge, arXiv 2506.22316](https://arxiv.org/html/2506.22316v2)）；
- 长清单指令遵循退化是评测领域共识，标准解法一致：**把长清单分解成逐条/逐题的独立评估**（[Patronus AI LLM-as-judge 实践](https://www.patronus.ai/llm-testing/llm-as-a-judge)、[Evidently AI LLM Judges FAQ](https://www.evidentlyai.com/blog/llm-judges-faq)）；
- 对本项目的映射：整卷量规（8–10 大题 × 每题多条评分点）一次给 = 几十条判分指令同时活跃；逐题批改 = 每次只有 1 题的评分点活跃。**量规稀释与输出挤兑同源，分批一并解决。**

### 1.3 注意力/分辨率摊薄（整卷图的代价）

- 图像 token 按像素/切块计量（算力口径，与价格无关）：
  - OpenAI：512×512 切块，每块 170 token + 基图 85（[官方指引](https://developers.openai.com/api/docs/guides/images-vision)）；
  - Gemini：≤384px 双边 258 token，大图按 768×768 切块每块 258（[官方 token 文档](https://ai.google.dev/gemini-api/docs/tokens)）；
  - Qwen2/2.5-VL：像素/784；Qwen3-VL：像素/1024（[Qwen2-VL](https://qwenlm.github.io/blog/qwen2-vl/)、[Qwen3-VL](https://github.com/qwenlm/qwen3-vl)）。
- A4 300dpi 整页 ≈ 2480×3508 ≈ 8.7M 像素 ≈ **Qwen 口径 ~11k token / OpenAI ~6.2k / Gemini ~5.4k**；两页卷输入图像即 1.1 万–2.2 万 token 起步。
- 关键点：**每多一题，模型都要在这 11k+ token 的整页里重新定位**——定位本身消耗注意力，且手写小字在整页分辨率下占的有效像素很低。本库已有直接证据：`identify-papers.ts` 专门把首页顶部 28% 裁出来放大到 1400px 宽再读姓名（注释原话："整页缩小后手写小字难读"）——**裁剪放大在项目内已被验证有效**。
- 裁剪后的量级：一道大题作答区典型 600×800–1000×1200 像素 ≈ **0.5k–1.2k token，是整页的 1/8–1/10**。同样一道题，裁剪图把 token 花在"作答本身"上，有效分辨率反而高数倍。

### 1.4 多任务串扰

一次调用同时做：读题干 → 全卷定位 → 认手写 → 对评分标准 → 给分 → 写评语 → 算 box 坐标。任务越多，单任务质量越差（多任务干扰是通用结论）；RAND 的对照实验还提示"复杂流水线未必赢过简单清晰的单任务指令"（[RAND](https://www.rand.org/pubs/research_reports/RRA4618-1.html)）——**分批的本质是把多任务拆回单任务，而不是把流程搞复杂**。

## 二、现状盘点（同模型前提下，流程有哪些可动杠杆）

| 环节 | 现状 | 位置 | 与本方案的关系 |
|---|---|---|---|
| 批改形态 | **整卷一次视觉调用**，全页原图+全量规 → 一次 JSON 出全部大题 | `grading-pipeline.ts` `gradePaperOnce` | 拆成"定位+分批" |
| 输出上限 | `GRADING_MAX_TOKENS = 8192`（整卷共享） | `grading-pipeline.ts:47` | 改为按批配给（1k–4k/批） |
| 量规粒度 | **大题级**（"一、选择题(10 小题×5 分)"是一条 50 分的题） | `rubric-extract.ts` 拆题规则 | 需细化到小题/题组（`rubric-refine.ts` 未提交稿已走在路上） |
| 评分点 | `presetMarks`（逐题扣分点，负分制）+ 合成钳制 | `shared/types/grading.ts`、`markScoreFromSelection` | 直接复用：每批 prompt 只带本批题的评分点 |
| 批注框 | AI 每大题返回 `box{page,x,y,w,h}`（0–1 归一化） | `grading-pipeline.ts` 解析 | 痕迹打印在用；分批后 box 天然精确到"本批区域" |
| 客观题判分 | 也走大模型直接给分 | 同上 | 改"转写+规则判分"（09-13 保留项） |
| 缓存 | 量规进 system prompt + `sessionId: grading:<taskId>` 短缓存 | `gradePaperOnce` 请求参数 | 分批后 sessionId 按"批类型"组织，同批全班复用，缓存保留 |
| 失败路径 | 单卷失败标 failed 可重试；重改作业自动重试一次 | `startGrading`/`regradePapers` | 复验的"重改一次"复用同一套回滚/重试骨架 |
| 复核台 | 教师逐题覆盖、发布门槛 | `TeacherReview` 体系 | 复验不一致的题**置顶**复核台（教师=仲裁终评） |
| 裁图先例 | `identify-papers.ts` 顶部裁剪放大（28%→1400px） | `buildHeaderCrop` | 裁剪管线的本地模板，`@napi-rs/canvas` 现成 |
| 进度事件 | phase: start/identify/graded/failed/done | `GradingProgressPayload` | 分批后需加 phase（如 `stage`），渲染层进度展示适配 |

**结论：可动杠杆全部在流程层，不需要换任何模型。**

## 三、外部证据

### 3.1 裁剪/聚焦对视觉判读的影响（"把那一块截出来单独批阅"的依据）

| 证据 | 结论 | 来源 |
|---|---|---|
| **Set-of-Mark (SoM)** | 在图上叠加编号标记后，GPT-4V 指称定位精度 **25.7% → 86.4%**（RefCOCOg ACC@0.5），零训练 | [arXiv 2310.11441](https://arxiv.org/abs/2310.11441)、[项目页](https://som-gpt4v.github.io/) |
| **红圈提示（visual prompting）** | 简单红圈即可把 CLIP/VLM 注意力导向目标区域，优于随机与多数裁剪策略 | [arXiv 2304.06712](https://arxiv.org/html/2304.06712v2) |
| **TextCoT（先概览→放大裁剪）** | 免训练的"粗定位+物理裁剪放大"两步链，专治文字密集图 VQA；消融显示粗定位仅 +0.58%，**物理裁剪放大带来主要增益** | [arXiv 2404.09797](https://arxiv.org/html/2404.09797v1) |
| **V\* / thinking with images** | 把"裁剪/放大/旋转"做成模型自主工具后，V\* 视觉搜索基准达 95.7%——**"先找区域再细看"正被内建为下一代模型能力**（对本项目意味着：外部裁剪层是当下把老模型用到新模型水平的桥） | OpenAI thinking with images（经 [SoM 相关综述与检索摘要](https://arxiv.org/abs/2310.11441)交叉印证） |
| **本库先例** | 卷面认人：顶部 28% 裁剪放大 1400px 后手写姓名可读性显著改善（"整页缩小后手写小字难读"） | `identify-papers.ts:116-145` |
| **商用同构** | 阿里云 AI 阅卷："智能分题——**按需圈定题目区域**，支持整卷/单题"，客观/主观双通道判分，"评分差异大自动触发人工复核" | [阿里云 AI 阅卷](https://www.aliyun.com/benefit/scene/aiyuejuan)（营销页，无准确率数字，采信其**流程形态**而非指标） |

### 3.2 量规分解与复验（"改完复查一遍，不一致重改"的依据）

| 证据 | 结论 | 来源 |
|---|---|---|
| **自洽性（同模型多次采样+投票）** | GSM8K 上 40 路采样多数投票比贪心 CoT **+17.9%（绝对）**；推理任务普遍增益 5–25%。**同一模型即可获得，不依赖第二个模型** | [Wang et al. 2022, arXiv 2203.11171](https://arxiv.org/abs/2203.11171) |
| **LLM 单次评分有方差** | 同一输入多次打分结果漂移，小差异可能只是裁判方差而非真实分歧——单次评分不可全信，多趟聚合是标准解 | [Rating Roulette, EMNLP 2025 Findings](https://aclanthology.org/2025.findings-emnlp.1361.pdf)（09-13 调研已引，结论沿用） |
| **量规长度/顺序伤判分** | 多条目量规一次给会稀释判分质量；解法=分解为逐条评估 | [arXiv 2506.22316](https://arxiv.org/html/2506.22316v2) |
| **分歧是信号** | 双评分歧大的条目正是需要第三方介入的条目——分歧可直接驱动复核优先级 | 高考双评制度同构（见 3.3）；[Arize: Human-LLM judge alignment](https://arize.com/blog/measuring-human-llm-judge-alignment/) |
| **思考预算与判分质量** | 推理 token 计入输出上限（见 1.1）——给足思考空间是"判得准"的前提，分批的本质是给每题配足思考预算 | [OpenAI 社区/官方](https://community.openai.com/t/why-was-max-tokens-changed-to-max-completion-tokens/938077)、[OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) |

### 3.3 行业阅卷流程（"分步骤、分题型、有复查"的老祖宗就是网上阅卷）

中国高考/大规模考试的网上阅卷是**分阶段批改流程的最成熟模板**（全部有官方/权威来源，09-13 调研已引证，本节沿用并补新证）：

1. **三段式流程**：扫描 → **客观题机器判分**（涂点识别，不占人工）→ **主观题分题切块、一屏一题、流水阅卷**（每位老师只批一道题，效率与尺度一致性双收）→ 合成总分（[中国教育和科研计算机网：网上阅卷系统揭秘](https://www.edu.cn/)；[专利 CN1598845A：答题卡图像切割与分发、主观题评分误差控制](https://patents.google.com/patent/CN1598845A/zh)）。
   —— 对本项目的映射：**"每位老师只批一道题"就是"每次调用只批一道题"的人类版本；尺度一致性正是准确率。**
2. **双评+阈值仲裁**：背靠背双评，分差 ≤ 阈值取均值，超阈值自动三评，仍分歧交专家仲裁（[教育部](http://www.moe.gov.cn/jyb_xwfb/s5147/201206/t20120615_137820.html)、[新华网评卷现场](https://www.news.cn/politics/2022-06/14/c_1128741496.htm)）；北京理科阅卷阈值 ≈ **题目分值的 1/6**（[新京报](https://m.bjnews.com.cn/detail/155143991414237.html)）。
3. **AI 辅助质检的实绩**：浙江省教育考试院在保持人工双评仲裁不变的前提下引入 AI 质检，评卷一致率 98.55%/99.08%（[浙江省教育考试院](https://www.zjzs.net/attach/0/a3640bfb228848ad8822cda219ebe945.pdf)）。
4. **分步给分的评分细则文化**：高考物理评分细则天然是"逐步骤评分点"——与 `rubric-refine`（参考答案→逐题扣分点）完全同构。

### 3.4 批改顺序：诚实的结论

**没有找到"先改单选比先改大题更准"的直接证据**——分批之后各批是独立调用，互不抢预算，顺序对准确率本身影响很小。顺序的真正价值：

| 价值 | 机制 |
|---|---|
| 客观题先锁定 | 转写+规则判分近零成本零判分错误，先出分增强对流程的信任 |
| 失败早暴露 | 量规错误/配置错误/图片问题在第一批（便宜批次）就失败，止损 |
| 渐进反馈 | 分数逐批出来，老师在等待期可先复核已出题（复核台提前开工） |
| 与人一致 | 网上阅卷=客观先行；教师手工批卷也先对客观题答案 |

**推荐采纳用户提议的顺序：单选 → 多选 → 填空(1–2 小题/批) → 大题逐题**。同时明确：这个顺序是"成本结构与体验最优"，不是"准确率最优"——准确率由"分批+裁剪+复验"三个机制扛。

## 四、流程总设计（L0–L3 四层管线）

```
L0 量规准备（每任务一次，不随卷数增长）
   ├─ 拆小题：量规粒度 大题 → 小题/题组（rubric-extract 的拆题规则 + rubric-refine 扣分点）
   └─ 母版定位（可选，P2）：样卷一次调用标出每题作答区 → 全班复用（与痕迹回写 P2 共用基础设施）

L1 分批批改（每份卷 N 次调用，按题型分批）
   ├─ 单选批：裁剪选择题作答区（或整卷缩略+区域框） → 只转写答案 "1-5 BACDA" → 规则判分
   ├─ 多选批：同上（转写+规则判分）
   ├─ 填空批：1–2 小题/批 → 转写+等价判定（规则比对为主，模型兜底语义等价）
   └─ 大题批：逐题一次调用：裁剪图 + 本题量规/评分点 → 思考+给分+批注+box
        每批输出上限独立配给（转写批 ~1k，大题批 2–4k）

L2 条件复验（只对触发题，期望次数 = p × 题数）
   ├─ 触发信号（全部可观测，不需要概率校准）：
   │    ① 模型自报"字迹不清/未作答/不确定"  ② 分数贴 0 或满分边界
   │    ③ 解析可疑（缺字段/修复解析兜底过）  ④ 客观题转写与规则判分冲突
   │    ⑤ （复验后）两次分差 > max(1, 满分/6)
   ├─ 复验方式（配置项，默认同模型）：
   │    same-model：同模型再判一次（自洽复验，冷启动/温度差异下采样）
   │    cross-model：配置第二个模型交叉复验（可选档，不是前提）
   └─ 分歧处理：不一致 → 重改一次（第三次）→ 仍不一致 → 该题标记"分歧"置顶复核台
        （= 高考"三评+仲裁"，仲裁人=教师，与"最大限度减教师负担"不冲突：只看被推到眼前的少数题）

L3 合成与兜底
   ├─ 分数合成沿用现体系（presetMarks 合成/钳制/教师覆盖优先）
   ├─ 复核台按"分歧度"排序（分歧题置顶 → 字迹不清 → 未作答 → 正常）
   └─ 回归集：AI 分 vs 教师生效分逐题差异统计（发布后自动算，做换档依据）
```

### 4.1 批次划分表（一份典型物理卷：10 单选 + 4 多选 + 4 填空 + 4 大题）

| 批次 | 内容 | 调用方式 | 每次输入 | 输出预算 | 判分者 |
|---|---|---|---|---|---|
| b1 | 单选 1–10 | 1 次转写 | 选择题区裁剪图(~1k) + 说明 | ~1k | **规则** |
| b2 | 多选 1–4 | 1 次转写 | 同上 | ~1k | **规则** |
| b3–b4 | 填空(2 小题/批) | 2 次 | 填空区裁剪图 + 该 2 题参考答案 | 1.5–2k | 规则为主，语义等价模型兜底 |
| b5–b8 | 大题逐题 | 4 次 | 本题裁剪图 + 本题评分点 | 2–4k/题 | 模型 |
| vN | 复验 | p×题数 | 同 b 批（图已裁好可复用） | 同 b 批 | 模型 |

合计：**基础 8 次/卷 + 复验期望 0.5–2 次/卷**（p=10–30%）。

### 4.2 输出预算重分配（本次提准的主发动机）

| 形态 | 每题可用输出+思考预算 |
|---|---|
| 现状（整卷 8192，8 大题+思考共享） | **~300–800 token/题（含思考），常态挤兑** |
| 分批（大题批 2–4k/题独立） | **2k–4k/题，思考可展开** |

分批不是把 8192 摊薄成 8×1024——而是**每批独立给足预算**，因为每次调用的输入成本（裁剪图 ~1k token）远小于输出挤兑的准确率代价。这是"次数换质量"的核心交换比。

### 4.3 裁剪三级策略（"先识别一遍，然后裁剪，然后改卷"）

| 级别 | 做法 | 每卷成本 | 适用 |
|---|---|---|---|
| ① **母版定位（推荐 P2 目标态）** | 样卷（干净卷）一次调用标出每题作答区 → 之后每份卷只需把"卷面"对齐到母版（复用痕迹回写 P2 的基准点/单应检测），区域坐标全班复用 | 定位 1 次/任务；逐卷仅本地几何计算 | 自印卷/答题卡，版式统一 |
| ② 逐卷定位调用 | 每卷一次"版面定位"调用（整页图 → 输出每题 box JSON）→ 再按 box 裁剪分批批改 | +1 次/卷（输出 ~0.5k） | 版式不统一/学生自带纸 |
| ③ 现状顺带 box（P1 过渡） | 各批批改时带整页缩略图 + "先给本题区域再判分"（模型自己定位）；box 精度粗但零额外调用 | 0 | 上线初期、验证分批收益 |

本地零 token 备选：PaddleOCR PP-DocLayout 版面检测（23 类含**试卷**场景，输出区域坐标，[官方文档](https://paddlepaddle.github.io/PaddleOCR/main/version3.x/module_usage/layout_detection.html)）——但引入本地 CV 组件是另一条工程线，**只作备选记录，不进主线**（主线坚持"同一模型、纯调用编排"）。

裁剪注意（来自痕迹回写调研的既有结论）：AI 逐卷 box 有 ±5–10mm 抖动，**裁剪要外扩**（区域四周 +15–20% 余量 + 相邻题号上下文），宁可多带一点邻题，不可截断作答；跨页大题取两页并裁或回落整页。

### 4.4 复验的期望成本公式（"以次数校验"的账）

设每卷基础调用 N 次，复验触发率 p（触发题数/总题数），复验每次 1 调用：

```
期望总次数/卷 = N + p × 题数          （p=20%, 22 题物理卷: 8 + 4.4 ≈ 12.4 次）
对比：全量双评 = 2N                    （16 次，09-13 已否决）
现状整卷 = 1 次（但输出挤兑 + 准确率惩罚）
```

再乘每次 token（裁剪后单次输入 ~1.5–2k vs 整卷 ~12–24k）：**分批+条件复验的总 token 与"整卷跑两次"相当，但每题质量决定性地更高**。触发率 p 本身是配置项，钱紧调严（只触发自报不清/解析可疑），钱松调宽（全部主观题复验）。

### 4.5 客观题规则判分（并入本流程，09-13 保留项落地）

- 单选/多选批次：prompt 只要求**转写**（"读出该生每小题所选字母，只输出 JSON"），判分 = 转写串与 `referenceAnswer` 逐位比对（归一化大小写/全半角）；
- 收益：判分错误清零（只剩"认读错"一类风险，而认读在裁剪放大后错误率大降）；输出只有一行字母串，1k 预算绰绰有余；
- 转写与规则判分冲突天然不存在（判分是确定性的）；**转写自信不足**（模型自报某题字迹不清）才进复验。

## 五、成本-收益量化（同一模型，相对倍数口径）

> 全部以"现状整卷 1 次调用"为 1× 基准；token 用 Qwen 口径（像素/784）近似，各家长比例一致。

| 方案 | 调用次数/卷 | 输入 token/卷（图像为主） | 输出+思考预算/题 | 判分质量预期 |
|---|---|---|---|---|
| 现状：整卷一次 | 1 | ~23k（2 页原图+全量规） | ~300–800（挤兑） | 知识点多时直线下降 |
| 全量双评（已否决） | 2 | ~46k | 同现状 ×2 次独立 | 提升有限（单次仍挤兑） |
| **分批+裁剪（无复验）** | ~8 | **~14–18k（比现状更低）** | 2k–4k（充足） | 主观题显著提升（机制 1/2/3/4 全解） |
| **分批+裁剪+条件复验（推荐）** | ~8 + p×题数（典型 10–13） | ~18–24k | 充足 + 双采样校验 | 再叠加自洽性收益（5–25% 区间的错误被捕获） |
| 分批但不裁剪（每批仍送整页） | ~8 | ~90k+（**爆表，不可取**） | 充足 | 提升但算力浪费——**裁剪是分批的前提** |

**核心交换比一句话：把"整卷一次"拆成"裁剪后的多次"，用几乎相同的总 token，换来每题 5–10 倍的输出/思考预算 + 聚焦的视觉输入 + 独立的复验校验。**

## 六、准确率提升来源映射（每个机制 → 证据 → 预期）

| 机制 | 对应病灶 | 证据强度 | 预期收益 |
|---|---|---|---|
| 输出预算重分配（分批） | 1.1 挤兑 | 机制性（官方文档+算术），无需实验确认上限存在 | 思考展开，长评分点题受益最大 |

## 七、分阶段落地（供拍板，本文档不实施）

### P1 — 分批 + 预算重分配 + 规则判分（不动裁剪，最大收益/最小风险）

1. 量规粒度细化到大题内小题/题组（`rubric-refine` 未提交稿并入，客观大题按小题拆扣分点已在其中）；
2. `gradePaperOnce` 拆为按批循环（题型序：单选→多选→填空 1–2 题→大题逐题），每批独立 maxTokens（转写 1k / 填空 2k / 大题 4k）；
3. 单选/多选批改"转写+规则判分"（新增一个纯函数判分器 + 单测）；
4. **回归集对比脚本**（前置项）：已复核任务 JSON → 旧/新流程逐题差异率报告；
5. 进度事件加 phase（stage 级），UI 显示"第 x 批/共 y 批"。

### P2 — 裁剪 + 条件复验（本方案的完整形态）

1. 逐卷定位调用（4.3 ②）或母版定位（4.3 ①，与痕迹回写 P2 共用基准点/单应检测与样卷留档）；
2. 裁剪执行器（`@napi-rs/canvas`，外扩 15–20%，跨页合并——`buildHeaderCrop` 同款技术）；
3. 复验层：触发信号收集 → same-model 复验 → 分歧重改一次 → 仍分歧置顶复核台；
4. 复核台排序（分歧度优先）；任务 JSON 增复验留痕字段（两次分/触发原因/最终采用）。

### P3 — 校准与自动化（长期）

1. 离线校准（L4 思想）：发布后逐题统计 AI vs 教师偏差，系统性偏差自动注入下次量规修正提示；
2. 锚点卷校准（L3 思想）：开批前 3–5 份教师复核过的标杆卷做 few-shot；
3. 档位"拨盘"配置化：批粒度（逐题/题组/整卷）、复验档位（off/same/cross）、触发阈值——模型变强后拧回粗粒度，回归集数据决定何时拧。

## 八、风险与开放问题

| 风险 | 说明 | 缓解 |
|---|---|---|
| 裁剪截断作答 | box 抖动 ±5–10mm，可能裁掉作答末行 | 外扩 15–20% + 带题号上下文；母版定位根除（P2） |
| 次数上升放大单次瞬时失败 | 8–12 次/卷，任何一次失败都影响该卷 | 沿用重改作业的"失败回滚+重试一次"骨架；批次级失败只重试该批 |
| 缓存命中率变化 | system prompt 从"全量规"变"批级量规" | sessionId 按批类型组织，同批全班 50 份仍全量命中 |
| 转写串与答题卡格式差异 | 手写 ABCD 潦草/改涂 | 转写批带"不确定则标记"出口 → 进复验 |
| 复验引入的时延 | 串行下每卷多几趟 | 批内串行、卷间可并发（现状已串行，P2 可评估 2–3 路并发） |
| 顺序的过度期待 | 顺序本身不提准（3.4 诚实结论） | 文档明确预期，防止后续把顺序当救命稻草 |

**开放问题**：①填空题"语义等价"的规则边界（1.5m 与 150cm 谁判等价）——建议物理学科单位归一化规则先行，等价判定模型兜底；②复验触发率 p 的初始值（建议先全量记录触发信号、只对"自报不清+解析可疑"两档触发，跑两个任务看分布再放宽）；③跨页大题的裁剪策略（两页并拼 vs 回落整页）实测拍板；④母版定位与痕迹回写 P2 的共用件（样卷留档、基准点检测）合并排期。
