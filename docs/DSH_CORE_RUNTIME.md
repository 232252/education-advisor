# DeepSeek 核心运行时规划（已定）

- 状态：已拍板。方向变更须再明确同意。
- 日期：2026-11-11
- 范围：教育参谋桌面端随包的 DeepSeek Harness 底层。不改变「Latest 仍是 v3.3.3、未确认不合并正式版」的发布纪律。
- 相关文档：[插件化远景](./DSH_PLUGIN_VISION.md)、[架构总述](./ARCHITECTURE.md)、[安装包离线瘦身](./superpowers/specs/2026-11-09-installer-offline-slim.md)、[官方插件标准与产品插件化计划](./DSH_PLUGIN_STANDARD.md)

这份文档把三件事定死：底层用哪些能力、哪些只是官方界面可以丢掉、以后官方小升级怎样做到改版本号再跑 GitHub CI 就能跟上。

---

## 1. 已定原则

1. **底层用 DeepSeek Harness，不换回 pi。** 教师对话和智能体循环已经走 `dsh --profile sdk`。pi 只做模型目录和密钥侧的兼容层，不是插件宿主，不能再当驱动。
2. **要功能，不要官方界面。** 官方「探索未至之境」网页壳、会话首页、终端侧栏、品牌和设置页等显示层不进安装包，也不嵌进「对话」。Agent 循环、工具调用、插件系统和连接中心（IM）这些实际能力都要留。
3. **大部分能力都留在运行时里。** 不因为暂时不对教师模型开放，就把官方工具包从运行时删掉。包在，以后能用；对模型可见与否，用补丁按行 id 开关，和「装没装」分开。
4. **小升级要对齐官方，少改宿主。** 同主线的小更新（补包、修 bug、加渠道、加工具行）应做到：改一处版本号，跑 GitHub CI，通过就打测试预发布。只有官方公开 API 或加载模型发生大变动时，才接受这边重构。
5. **禁止用行号或改官方前端源码来适配。** 补丁只认 cordis 行 id 和已约定的公开接口。魔改官方界面越深，每次升级越贵，这正好是要避免的。

---

## 2. 三块核心（都要）

教育参谋自己的窗口、对话页、批改页、设置页始终是壳。DeepSeek 提供下面三块底层，缺一块都不算完整。

### 2.1 连接中心

已经决定把官方 `@xmanrui/dsh-im` 打进来，用来登录和连接飞书、企微、钉钉、QQ 等渠道。这是功能，不是「探索未至之境」那张官方首页。

打开连接中心时，只应落到 IM 面板（`eaa-panel`，默认飞书）。不要把官方 Harness 会话页当作连接中心。IM 面板自己的界面属于连接功能，要留；Harness 的品牌、会话列表、插件市场入口、GitHub 按钮属于官方壳，不要当产品面子。

渠道消息和教师对话走同一套教育工具、同一套加固补丁、同一批模型密钥。

### 2.2 插件系统

Cordis 加载器 + `dsh-plugin-manager` 是以后加功能的正路。现有教育插件（操行、花名册、成绩、批改）和 dsh-im 都按插件装进 `sdk`（教师对话）和 `web`（连接中心）两个 profile。

以后加能力，优先在本仓库写成插件，打包时预装进 sdk / web profile，不改 Electron 主程序。官方插件市场的网页不必随包。教师机不带 pnpm，也不在现场执行 `dsh plugin add`：现有工具和插件以随包预装为准，以后新插件也是开发完成后再打进安装包。

### 2.3 本地运行时（agent 循环）

教师对话通过 `@deepseek-ai/dsh-sdk-client` 拉起随包 Node 上的 `dsh` 子进程，profile 固定为官方 **`sdk`**（`dsh-base` + `dsh-sdk-app`）。不要改用 `dsh-sdk-minimal`：它不经过 `dsh-base`，插件和技能不完整，还自带常驻 shell，升级路径也和现在这套不一致。

循环里已经映射到教育参谋事件、可以做到「对话」界面上的有：

- 流式文本和思考过程
- 工具调用的开始、参数、结果（对话里只显示工具自己的名字）
- 一轮结束、token 用量
- 技能加载（`dsh-tool-skill` + 钉死的技能目录）

这些用教育参谋自己的对话 UI 订阅 SDK 事件来呈现，不嵌官方聊天页。

当前对模型关闭、但运行时里仍保留的官方能力（以后若要开放，只改开关，不必重新打包一类新引擎）：bash / 终端、任意读写文件、网页搜索与抓取、子代理、计划模式、官方 workflow、模型侧的插件管理器等。关闭原因是教师机最小权限，不是功能废弃。

## 3. 随包范围

升级时不要维护一份「每个 npm 包的白名单」——官方每加一个包都要改名单，这会把小升级拖成适配。随包以官方 **profile** 为单元，再用**稳定的排除规则**去掉显示层。

### 3.1 必留：官方 sdk 运行时（功能）

以官方 `dsh --profile sdk` 的闭包为准，主要包括：

| 类别 | 代表包 / 组成 | 作用 |
| --- | --- | --- |
| 进程入口 | 随包 `dsh-node`、`@deepseek-ai/dsh` 启动器、`dsh-sdk-app`、`dsh-sdk-jsonrpc-server` | 子进程和 JSON-RPC |
| 宿主客户端 | `@deepseek-ai/dsh-sdk-client`、`dsh-sdk-protocol`、`dsh-session` | 教育参谋主进程接入循环 |
| Agent 循环 | `dsh-agent`、`dsh-agent-loop`、`dsh-system-prompt`、`dsh-agent-instructions`、compaction、token-meter | 推理、压缩、用量 |
| 模型 | `dsh-llm`、`dsh-llm-pi-ai`、`dsh-llm-retry` 及官方适配 | 实际调用；目录仍由本仓库的 pi-ai 兼容层提供 |
| 插件宿主 | `cordis` 与官方 loader、`dsh-plugin-manager` | 装插件、按 profile 组合 |
| 工具基础设施 | `dsh-tools`（注册表）、`dsh-tool-executor-native`（MCP 桥依赖，不能关） | 没有这两样，教育工具也调不起来 |
| 技能 | `dsh-skill`、`dsh-skill-filesystem`、`dsh-tool-skill` | 技能正文仍在本仓库，由官方工具加载 |
| 会话与存储 | `dsh-session-*`、本地 credentials / storage | 会话日志与状态 |
| 官方工具包 | `dsh-tool-bash`、`dsh-tool-fs`、`dsh-tool-web`、`dsh-tool-subagent` 等随 `dsh-base` 带上的工具 | **装上，默认不对教师模型开放** |
| 教育插件 | `vendor/eaa-tools`、`eaa-roster`、`eaa-grades`、`eaa-grading` | 对话和连接中心共用 |
| 连接中心 | `@xmanrui/dsh-im`、`integrations/eaa-panel`，以及能让 IM 面板跑起来的最小 web 宿主 | 渠道登录与收发 |

Office 转 PDF 用的 `office-kit`、随包 Node，属于产品功能或运行前提，不是官方界面，继续留。

### 3.2 必去：官方显示层（界面）

用模式排除，不按小版本逐个点名。新版本若再增加同类界面包，只要仍符合这些前缀，打包规则不用改。

| 排除规则 | 说明 |
| --- | --- |
| `@deepseek-ai/dsh-client-ui-*` | 官方网页组件，约 60 个包。这是「显示层」的主体 |
| `@deepseek-ai/dsh-web-frontend` | 「探索未至之境」前端 |
| 官方品牌 / 账号 / 遥测界面 | 如 `dsh-client-ui-brand-official`、账号设置页、产品分析界面 |
| 实验包里的界面 | `dsh-experimental-client-ui-*` |
| 官方插件市场网页 | `dsh-plugin-market` 的界面；后台若被 plugin-manager 依赖则随功能留下，但不把市场页当产品 |

说明：当前完整运行时里，官方界面包大约 28 MB，网页前端大约 6 MB，**并不是磁盘上的大头**。616 MB 运行时里约 424 MB 是 pnpm 安装器。丢掉界面主要是为了：产品不再露出官方壳、少占运行内存、少一条要跟着魔改的前端。体积上真正该收的是整份 pnpm 工具链（见 3.4），不是把功能删掉。

连接中心若仍需极少量布局 / 槽位包才能把 IM 面板嵌进来，只留 IM 宿主用到的那些，并在下方 CI 里列成「宿主例外」，避免整套 `dsh-web-app` 滑回来。

### 3.3 现在不预装、但不禁止未来用

- 官方实验功能束（agent team、voice、liveshare、forge 等）：默认不进教师安装包。若以后要某项**功能**（不是它的官方界面），再按插件或官方 bundle 加，不提前堆进默认包。
- 教师机现场用 pnpm 拉依赖，或为以后 `dsh plugin add` 保留 `@pnpm/exe`：都不要。现有工具以随包预装为准；运行时不携带 `pnpm` 目录，也不携带 `@pnpm/exe`。

---

### 3.4 不随包：pnpm 工具链

教师机不需要包管理器。官方 `dsh plugin add` 内部会调用 pnpm，这条路径在教师安装里关闭，找不到 pnpm 时官方会报 `pnpm-missing`，这是预期行为。

新能力只在开发侧完成后打进下一版安装包。对话、工具调用、连接中心 IM 以及当前已经随包的教育插件，都不依赖教师机上的 pnpm。

当前已解压运行时里，这项大约 454 MB：`pnpm` 目录约 404 MB，其实是同一份约 50 MB 程序的 8 个副本；外加一份内容相同的 `@pnpm/exe`（约 50 MB）。开发机和 CI 打包时仍可使用仓库里的 pnpm，只是不放进教师安装包。

## 4. 小升级如何做到「跑 CI 就行」

目标：DeepSeek 发一个同主线小版本时，这边的工作是改 pin、跑 GitHub Actions、看门禁、打预发布，而不是再做一轮适配。

### 4.1 升级单元

- **只在一处锁定官方版本**（当前是 `0.2.2-rc.1` 这一组 `dsh-*` / `dsh-sdk-*`，以及单独锁定的 `@xmanrui/dsh-im`）。 bump 时改这一处，由现有打包脚本展开闭包。
- **运行时按官方 `sdk` profile 取功能闭包**，再按第 3.2 节的模式去掉显示层。不要改成「我们自己点名要哪 80 个包」——那会让每次官方加包都变成一次规划。
- **连接中心跟 dsh-im 的发布走**，继续用约定的 `dshImClient` 接口（当前 v1：`render` / `setSettingsVisible`），不在主程序里打补丁改插件源码。

### 4.2 适配只能走稳定面

允许的适配点只有这些：

- cordis 行 **id**（加固补丁、教育预设）：官方新增一行时，旧 id 仍然有效；未知的新工具行由 CI 揭出来，补进允许或关闭名单即可。
- SDK 公开方法：`initialize` / `prompt` / `subscribe` / `close`。
- dsh-im 公开客户端：`dshImClient` 主版本和面板方法。
- 本仓库自己的事件映射（`stream-mapper`）和教育插件。

不允许的适配点：

- 按官方源码行号打补丁，或直接改 `dsh-web-frontend` / `dsh-client-ui-*`。
- 把官方会话界面嵌进「对话」后再跟版本做样式对冲。
- 用「上次安装戳的版本号」跳过插件重链（路径变了也必须重装）。安装戳必须带上解析后的插件目录，否则小升级解压到新路径后，功能会静默丢。

### 4.3 GitHub CI 门禁（小升级的全部人工点）

在现有 Quality gates / Release 工作流上固定下面几类检查。小升级 CI 红了，优先只改名单或 pin，不改产品逻辑。

| 门禁 | 失败时怎么处理 | 目的 |
| --- | --- | --- |
| 官方 sdk 工具 / 插件行清单 | 新出现的模型侧工具行未进入「允许」或「关闭」名单则失败 | 官方新加工具时，补一行 id，避免漏关导致教师机暴露 shell |
| SDK 客户端表面 | `HarnessClient` 仍暴露约定方法，否则失败 | 小更新改了方法名，会在 CI 暴露，而不是装到教师机才坏 |
| dsh-im 合约 | `dshImClient.version` 与面板方法仍在，否则失败 | 连接中心跟官方插件小升 |
| 随包形态 | 运行时中不得出现第 3.2 节排除的显示层；必须包含 sdk 闭包、插件宿主、dsh-im、教育插件 | 防止以后打包脚本又把官方壳打回来，或把功能打丢 |
| 已有单测与打包 | 现有 hardening、preset、im-host、Quality gates 继续跑 | 回归 |

一条建议的小升级操作顺序（写给以后的 Release / 手工 bump）：

1. 只改官方版本 pin（dsh 一组，必要时再改 dsh-im）。
2. 推到分支，等 GitHub CI。
3. 若只是「新工具行未登记」，在加固或允许名单里补 id 后再跑。
4. CI 全绿后，按现有纪律打**预发布**（Latest 仍留正式版，不自动提升）。

### 4.4 什么算小更新，什么算必须重构

| 算小更新（应对齐「跑 CI」） | 算大变动（接受重构） |
| --- | --- |
| 同主线修订号、补丁号；新增官方工具行或包 | `HarnessClient` 初始化 / 会话 / 事件协议不兼容 |
| dsh-im 加渠道，但 `dshImClient` 主版本不变 | `dshImClient` 主版本变化，或面板不再提供 `render` |
| `dsh-base` / `dsh-sdk-app` 内部实现调整 | 官方取消或拆掉 `sdk` profile，或 cordis 加载模型变更 |
| 显示层又多了符合排除前缀的新包（规则已覆盖，不必改打包） | 连接中心不再能在独立 web 宿主里运行，必须换嵌入方式 |

大变动出现时，再单独开一轮改造，不强行用「只改 pin」混过去。

## 5. 当前体积累积（2026-11-11，本机安装实测）

供对照，不是新的体积指标。按本决策，教师包应去掉全部 pnpm 工具链（约 404 MB 的 `pnpm` 目录，以及约 50 MB 的 `@pnpm/exe`），不能只丢掉显示层却仍带着安装器。

| 项目 | 大约体积 | 处理 |
| --- | --- | --- |
| 当前 Setup | 415 MB | 继续按离线全功能目标收，不靠删功能换体积 |
| 已安装目录 | 1.26 GB | 含未压缩组件包 |
| 首次解压后的 `dsh-bundles` | 687 MB | 运行时 + dsh-im |
| 其中 dsh 运行时 | 614 MB | 功能包（`@deepseek-ai` 合计约 61 MB）+ **pnpm 工具链约 454 MB（将从教师包移除）** + 其他 |
| 官方界面包 | 约 28–34 MB | 丢掉显示层，功能闭包留下 |
| 连接中心 dsh-im | 约 73 MB | 留下 |
| 随包 Node | 约 87 MB | 留下（官方运行时不认 Electron 自带 exe 的指纹） |
| office-kit | 约 69 MB | 留下（转 PDF） |
| pi-ai（模型目录） | 约 9 MB | 留下，不当驱动 |

## 6. 落地顺序

均先在本机改、装、测，通过后再推 GitHub、打测试预发布。不自动改 Latest，不把未确认的正式版覆盖上去。

1. **把本文定为随包与升级政策。** 在 CI 里补第 4.3 节门禁（可先在现有测试中加清单，再接到 Quality gates）。
2. **连接中心回到 IM 面板。** 插件链接必须指向当前解压目录；安装戳要带路径。不要再打开官方 Harness 首页。这是功能修复，不是改方向。
3. **打包按官方 sdk 闭包 + 显示层排除规则出运行时。** 现有插件在打包时预装进 profile；运行时不带 `pnpm` 树，也不带 `@pnpm/exe`。连接中心只用最小 IM 宿主。
4. **对话界面补齐循环可视化**（工具调用、思考、用量），始终用本应用 UI，不嵌官方页。
5. 之后的产品功能，按 [插件化远景](./DSH_PLUGIN_VISION.md) 和 [官方插件标准](./DSH_PLUGIN_STANDARD.md) 以官方 bundle / 技能形态往这层核心上加。模型设置是第一个按该标准落地的项：把路由写进 profile 层的 `llm-pi-ai` 配置，不再把 EAA/pi 目录事后 `--patch` 进 DSH。

## 7. 明确不做

- 不把教师对话的驱动换回 pi。
- 不把官方「探索未至之境」嵌进对话，也不再靠裁剪官方页来化妆。
- 不从运行时删除官方工具包，只为了「现在模型用不到」。
- 不把 `pnpm` 或 `@pnpm/exe` 随包。教师机不在现场安装插件；以后的插件都是开发完成后再打进安装包。
- 未经确认，不把本路线的包发成正式版或改 Latest。
